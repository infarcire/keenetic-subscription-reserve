# Автоматический резерв подписки Remnawave для Keenetic / XKeen / Mihomo

Установщик берёт **уже настроенную** персональную ссылку, User-Agent и HWID из `/opt/etc/mihomo/config.yaml`. Основной и резервный адреса обновляют один локальный файл. Mihomo использует один провайдер, поэтому серверы не удваиваются. При недоступности обоих источников сохраняется последняя корректная копия.

## Установка одной командой

Войти по SSH в **Entware под root**, обычно порт 222. Команда ниже предназначена для приглашения `~ #`, а не для CLI KeeneticOS `(config)>`:

```sh
/opt/bin/curl -fL --retry 2 --connect-timeout 10 --max-time 60 https://raw.githubusercontent.com/infarcire/keenetic-subscription-reserve/v1.0.0/install.sh -o /opt/tmp/install-sub-reserve.sh && /opt/bin/sh /opt/tmp/install-sub-reserve.sh
```

Скачивается фиксированная версия `v1.0.0`. Загрузчик проверяет SHA-256 трёх файлов перед их запуском. Токен GitHub не нужен.

Перед установкой:

- XKeen должен работать с Mihomo, подписка уже должна загружаться.
- В конфигурации нужен HTTP-провайдер `subscription_1` с основным доменом `https://sub.demon-cloud.pro/`.
- Должны быть установлены `curl`, `jq`, `mikefarah/yq v4`, `mihomo`, `sha256sum`.
- Должен быть настроен HTTP external-controller Mihomo. Его текущий порт и секрет считываются автоматически.

Установщик не меняет подписки в Remnawave и не создаёт пользователя. При нескольких провайдерах он переводит на резервирование только `subscription_1`. Не следует использовать его для другой схемы без адаптации.

## Что делает установщик

1. Сохраняет исходную конфигурацию и выбранные подключения групп.
2. Из текущего провайдера берёт персональную ссылку и заголовки. Для резервной ссылки заменяет только начало адреса на `https://sub.demon.sarl:8443`, сохраняя путь и параметры.
3. Загружает подписку и проверяет её структуру, уникальность имён и корректность конфигурации самим `mihomo -t`.
4. Переводит **тот же провайдер** на локальный файл и выполняет горячее применение конфигурации.
5. Восстанавливает выбранные подключения групп и запускает отдельную службу обновления.

Обновления выполняются при старте службы и далее **раз в час**. Если оба адреса недоступны, следующая попытка — **через пять минут**. Ошибка основного адреса, пустая подписка, неправильное содержимое или ошибка проверки вызывают попытку резервного адреса. Рабочий файл заменяется атомарно только после всех проверок; TLS-проверка включена.

Повторный запуск той же команды обновляет общие скрипты **активной** установки без замены персональных настроек и первоначальной страховочной копии. Если установка отключена или откачена, автоматическая переустановка останавливается для проверки состояния.

## Состояние и управление

```sh
/opt/etc/init.d/S98remna-subscription status
cat /opt/etc/remna-subscription/status.json
```

Вручную проверить обновление:

```sh
/opt/sbin/remna-subscription-update once
```

Откатить исходную конфигурацию:

```sh
/opt/bin/sh /opt/etc/remna-subscription/rollback.sh
```

Откат останавливает загрузчик, отключает его автозапуск и возвращает исходный HTTP-провайдер подписки. Первоначальная конфигурация и выборы групп находятся в каталоге `before-*`, путь которого записан в `/opt/etc/remna-subscription/install.json`.

Основные файлы:

| Назначение | Путь |
|---|---|
| Загрузчик | `/opt/sbin/remna-subscription-update` |
| Автозапуск | `/opt/etc/init.d/S98remna-subscription` |
| Персональные ссылки и заголовки, права 600 | `/opt/etc/remna-subscription/settings.json` |
| Последний результат без персональных ссылок | `/opt/etc/remna-subscription/status.json` |
| Единственный файл серверов, права 600 | `/opt/etc/mihomo/proxies/subscription-resilient.yaml` |

Не публикуйте файлы `settings.json`, `config.yaml`, файлы серверов или резервные копии. В этом репозитории их нет. На GitHub лежат только общие скрипты и инструкция. Ни GitHub, ни установщик не получают административный доступ к панели Remnawave.

## Проверки и ограничения

Проверено на Keenetic/Netcraze Ultra ARM64 с Mihomo v1.19.33, yq v4.52.4 и curl 8.12.1:

- Основной и резервный источники дали одинаковые 37 серверов.
- При имитации отказа основного источника использован резерв.
- При имитации отказа обоих сохранён прежний файл.
- Пустой HTTP 204 и неправильное содержимое HTTP 200 отвергнуты.
- Отдельный экземпляр Mihomo стартовал из локального файла без HTTP-провайдера и подхватил атомарные обновления файла.
- В рабочем провайдере осталось 37 уникальных имён; выборы групп сохранились.

Полная перезагрузка/отключение питания и все модели Keenetic отдельно не проверялись. Совместимость и доступность резервного адреса следует проверить на нескольких устройствах перед массовой установкой. Горячее применение конфигурации может привести к переподключению отдельных текущих соединений.

Резервный HTTPS-вход получает данные от основной панели. Это резерв пути получения подписки, а не автономная реплика панели/БД. При отказе панели роутер продолжает использовать сохранённый список, пока доступные VPN-ноды и учётные записи работоспособны.

На уже установленных роутерах требуется однократно выполнить установку. Из обычного HTTP-провайдера подписки невозможно доставить и запустить скрипт. Если есть административный SSH-доступ ко всем устройствам, установку можно выполнять по списку с индивидуальными данными доступа.
