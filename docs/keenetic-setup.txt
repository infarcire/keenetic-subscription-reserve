Пример для TorrServer: Netcraze Hopper, KeeneticOS 5.1.7, ARM64 (aarch64).

ВАЖНО: В инструкции есть два разных режима команд!
• CLI KeeneticOS — команды настройки самого роутера (dns-proxy, ip http).
• SSH / Entware (BusyBox ash, приглашение ~ #) — команды opkg, curl, TorrServer.
Не вводи команды одного режима в другом.

3. УСТАНОВКА XKEEN                           [SSH / ENTWARE]
════════════════════════════════════════════════════════════════════════

ОСНОВНОЙ ВАРИАНТ (из xkeen.txt):

opkg update && opkg upgrade && opkg install curl tar && cd /tmp
sh -c "$(curl -sSL https://raw.githubusercontent.com/jameszeroX/XKeen/main/install.sh)"

АЛЬТЕРНАТИВНЫЙ ИСТОЧНИК (вместо предыдущего, НЕ после него):

opkg update && opkg upgrade && opkg install curl tar && cd /tmp
sh -c "$(curl -sSL https://cdn.jsdelivr.net/gh/jameszeroX/XKeen@main/install.sh)"

XKEEN-UI (отдельно, если нужен интерфейс управления):

curl https://raw.githubusercontent.com/zxc-rv/XKeen-UI/main/setup.sh | sh

ПРИМЕЧАНИЕ: эти команды сохранены из твоего файла. Там используется
репозиторий jameszeroX/XKeen, а присланная тобой документация расположена
в Corvus-Malus/XKeen. Тождественность и актуальность скриптов не проверены.
Ссылка на документацию:
https://github.com/Corvus-Malus/XKeen#как-использовать-генератор-конфига

4. НАСТРОЙКА DNS-over-TLS / DNS-over-HTTPS     [CLI KEENETICOS]
════════════════════════════════════════════════════════════════════════

Выбери необходимые DNS-серверы. Приведённые ниже команды — варианты;
не требуется вводить всё сразу.

DNS-over-TLS (DoT):

  Cloudflare
    dns-proxy tls upstream 1.1.1.1 sni cloudflare-dns.com
    dns-proxy tls upstream 1.0.0.1 sni cloudflare-dns.com

  Google
    dns-proxy tls upstream 8.8.8.8 sni dns.google
    dns-proxy tls upstream 8.8.4.4 sni dns.google

  AdGuard
    dns-proxy tls upstream 94.140.14.14 sni dns.adguard.com
    dns-proxy tls upstream 94.140.15.15 sni dns.adguard.com

  OpenDNS
    dns-proxy tls upstream 208.67.222.222 sni dns.opendns.com
    dns-proxy tls upstream 208.67.220.220 sni dns.opendns.com

DNS-over-HTTPS (DoH):

  Cloudflare
    dns-proxy https upstream https://cloudflare-dns.com/dns-query

  Google
    dns-proxy https upstream https://dns.google/dns-query

  AdGuard
    dns-proxy https upstream https://dns.adguard.com/dns-query

  OpenDNS
    dns-proxy https upstream https://doh.opendns.com/dns-query

Включение dns-proxy:

dns-proxy enable
dns-proxy cache enable
dns-proxy listen all
system configuration save

ВАЖНО: в твоём исходном файле раздел назывался «Включение dns-proxy
и отключение обычного DNS». Эти команды включают DNS-прокси, но сами
по себе НЕ удаляют обычные DNS-серверы из остальных настроек роутера.

6. УСТАНОВКА TORRSERVER                      [SSH / ENTWARE]
════════════════════════════════════════════════════════════════════════

Рабочий вариант с твоих скриншотов: TorrServer MatriX.146 для ARM64.
Entware уже установлен. Штатный BusyBox wget у тебя не принял HTTPS,
поэтому используем curl из /opt/bin.

ШАГ 1. Скачать бинарный файл:

/opt/bin/curl -L -o /opt/bin/TorrServer https://github.com/YouROK/TorrServer/releases/download/MatriX.146/TorrServer-linux-arm64

ШАГ 2. Выдать права и запустить:

chmod +x /opt/bin/TorrServer && mkdir -p /opt/etc/torrserver && /opt/bin/TorrServer --port 8090 --path /opt/etc/torrserver

Каталог данных создаётся внутри команды запуска: отдельного шага
по созданию папок при установке не было.

Веб-интерфейс в твоей локальной сети:
http://192.168.1.1:8090

Если запущено прямо в SSH-терминале, Ctrl+C остановит процесс.
Перед следующим разделом убедись, что вернулся к приглашению ~ #.

════════════════════════════════════════════════════════════════════════
7. АВТОЗАПУСК TORRSERVER                     [SSH / ENTWARE]
════════════════════════════════════════════════════════════════════════

Создание скрипта S99torrserver — твоя исходная рабочая команда.
Вставлять ОДНОЙ строкой:

mkdir -p /opt/etc/init.d; printf '%s\n' '#!/bin/sh' 'case "$1" in' 'start)' 'pidof TorrServer >/dev/null || /opt/bin/TorrServer --port 8090 --path /opt/etc/torrserver >/dev/null 2>&1 &' ';;' 'stop)' 'killall TorrServer 2>/dev/null' ';;' 'restart)' '"$0" stop; sleep 2; "$0" start' ';;' 'esac' > /opt/etc/init.d/S99torrserver; chmod +x /opt/etc/init.d/S99torrserver

Создаётся файл /opt/etc/init.d/S99torrserver.
Для запуска после перезагрузки должен срабатывать штатный rc.unslung
Entware. Файлы ты проверил, но фактический запуск после перезагрузки
роутера по скриншотам пока не подтверждён.

════════════════════════════════════════════════════════════════════════
8. ПРОВЕРКА И УПРАВЛЕНИЕ                     [SSH / ENTWARE]
════════════════════════════════════════════════════════════════════════

Проверить скрипт и запуск Entware:

ls -l /opt/etc/init.d/S99torrserver
ls -l /opt/etc/init.d/rc.unslung

Проверить процесс:

pidof TorrServer

Управление службой:

/opt/etc/init.d/S99torrserver start
/opt/etc/init.d/S99torrserver stop
/opt/etc/init.d/S99torrserver restart

Финальная проверка автозапуска: перезагрузить роутер, дождаться
загрузки Entware и открыть http://192.168.1.1:8090.

9. АВТОМАТИЧЕСКИЙ РЕЗЕРВ ПОДПИСКИ             [SSH / ENTWARE]
════════════════════════════════════════════════════════════════════════

Добавлено 1 ноября 2026 года.
Репозиторий: https://github.com/infarcire/keenetic-subscription-reserve

Сначала настрой и проверь рабочую подписку в Mihomo через XKeen-UI.
Интерфейс обычно доступен по http://192.168.1.1:1000.
В /opt/etc/mihomo/config.yaml должен быть HTTP-провайдер subscription_1
с основной ссылкой https://sub.demon-cloud.pro/ПЕРСОНАЛЬНЫЙ_ПУТЬ.
Установщик считывает ссылку и заголовки сам: вручную вписывать токен,
HWID и резервный адрес не нужно.

Нужны уже установленные curl, jq, mikefarah/yq v4, mihomo и sha256sum.
Для другой схемы конфигурации сначала нужна адаптация установщика.

Войти по SSH в Entware под root (обычно порт 222, приглашение ~ #).
Это НЕ CLI KeeneticOS с приглашением (config)>.

УСТАНОВКА ОДНОЙ КОМАНДОЙ:

/opt/bin/curl -fL --retry 2 --connect-timeout 10 --max-time 60 https://raw.githubusercontent.com/infarcire/keenetic-subscription-reserve/v1.0.0/install.sh -o /opt/tmp/install-sub-reserve.sh && /opt/bin/sh /opt/tmp/install-sub-reserve.sh

Скачивается фиксированная версия v1.0.0; перед запуском файлов
проверяются контрольные суммы SHA-256. GitHub-токен не требуется.

ЧТО ПОЛУЧИТСЯ:
  Основная подписка -> при ошибке резервный адрес -> при отказе обоих
  сохранить последний рабочий список. Серверы не дублируются:
  Mihomo использует один локальный файл и прежний subscription_1.

Резерв: https://sub.demon.sarl:8443 с прежним персональным путём
и параметрами. Сохраняются User-Agent и HWID этого роутера.
Персональные данные остаются на роутере и не публикуются в GitHub.

Обновление: при старте службы, затем раз в час. Если оба адреса
недоступны — повтор через пять минут. Некорректный/пустой ответ
не заменяет рабочий файл. Проверка TLS включена.

Установщик сохраняет исходную конфигурацию и выбранные подключения
групп. Горячее применение может переподключить отдельные соединения.
Перезагрузка роутера для установки не требуется.

ПРОВЕРКА:

/opt/etc/init.d/S98remna-subscription status
cat /opt/etc/remna-subscription/status.json

В status.json успешный результат — result: ok; источник — primary
или reserve. kept_cache означает: источники не дали рабочую подписку,
предыдущий файл оставлен. Убедись, что нужные сервисы открываются
и список серверов в интерфейсе не удвоился.

ОБНОВИТЬ СЕЙЧАС:

/opt/sbin/remna-subscription-update once

ОТКАТ:

/opt/bin/sh /opt/etc/remna-subscription/rollback.sh

Откат останавливает загрузчик, отключает его автозапуск и возвращает
исходный HTTP-провайдер. Путь копии — в
/opt/etc/remna-subscription/install.json, поле backup_dir.

Повторный запуск команды установки обновляет скрипты активной
установки без замены персональных настроек и исходной копии.
Отключённую/откаченную установку сначала нужно проверить отдельно.

Проверено на одном Keenetic/Netcraze Ultra ARM64 с Mihomo v1.19.33:
основной/резервный адреса, имитация отказа одного и обоих источников,
отбрасывание неправильных ответов, кеш, обновление файла,
сохранение выбранных подключений. После настройки — 37 уникальных
серверов. Полную перезагрузку роутера в этом тесте не выполняли;
все модели отдельно не проверены.

Для старых клиентских роутеров нужна одна установка по SSH/при
обслуживании. После неё дальнейшее переключение автоматическое.
Одна подписка Remnawave скрипт на роутере установить не может.

Резервный адрес зависит от основной панели: отдельной копии панели
и БД он не создаёт. При отказе панели остаётся локальный кеш.
